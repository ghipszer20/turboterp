# The audit assigns courses to requirements by optimization, not first-fit

A course often could satisfy several requirements, but sharing limits allow it to count toward only some of them. First-fit assignment (walk the requirements, grab the first matching course) reports false gaps whenever it spends a course on the wrong requirement, and a wrong "you're missing a requirement" is the most damaging error TurboTerp can make. So an audit solves assignment as a matching/integer-programming problem across every requirement layer at once, honoring sharing limits. The same solver finds the smallest set of courses to fill gaps and reports overshoot.
